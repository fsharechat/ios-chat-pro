# iOS 消息发送面板液态玻璃重构方案

日期：2026-11-14
状态：已完成兼容材质与交互的代码实现，待真机验收；验证记录见 `docs/ui/玻璃态消息输入面板.md`
依据：用户提供的 Apple 信息 App 截图、当前工程实现、Apple 官方资料（见配套研究笔记）。

## 1. 设计结论

采用「独立圆形＋按钮 + 悬浮玻璃输入胶囊 + 键盘替换式功能面板」。视觉参考用户截图的轻量悬浮轮廓、薄高光和背景透色；交互借鉴微信的语音/键盘切换、表情与更多面板、按住录音。这里的微信描述是交互参考，不宣称复刻某个版本的精确布局或官方规范。

保留直接可见的语音、表情入口，不把常用操作全藏进＋。有文字时，发送替换语音按钮，＋始终可用。输入文字过程中发送附件后，原有文字和 @ 信息保留。

当前 Xcode 15.2 使用 UIKit 材质实现玻璃风格；升级至支持新 SDK 的工具链后接原生 Liquid Glass。两者保持同一布局和交互，不能把旧工具链实现宣称为原生液态玻璃。

## 2. 当前能力与不可回退清单

代码依据：`App/MessageInputBar.swift`、`App/EmojiPanelView.swift`、`App/ExtPanelView.swift`、`App/ConversationViewController.swift`。

| 能力 | 当前实现 | 重构要求 |
|---|---|---|
| 文本 | 多行 UITextView，36–120pt，高度封顶后内部滚动 | 保留原生编辑、选择、粘贴、撤销；保留发送前去首尾空白的语义 |
| 表情 | Unicode 表情，横向分页，退格键，页码 | 保留全部现有数据；插入到选区，退格按字符簇处理 |
| @ | 输入 @ 选人、长按群成员头像插入、@所有人、整块删除 | 保留 mentionedType/mentionedTargets 与选择器；切换模式不能丢失 mentionTokens |
| 语音 | AVAudioRecorder → M4A → 后台 AMR 转换，M4A 回退与本地缓存 | 保留格式、上传链路和本地播放缓存 |
| 相册 | 单选图片或视频 | 保留视频时长/缩略图处理；不退化成仅图片 |
| 拍摄 | CameraCaptureViewController 拍照与视频录制入口 | 保留照片和视频两条回调（实施时按当前代码核实） |
| 文件 / 位置 | 文档选择器 / 位置选择页 | 保留现有权限和发送回调 |
| 通话 | 更多面板，单聊音频/视频通话 | 群聊不出现这两个入口，不扩展群通话 |
| 收起 | 点消息区、拖动列表、退出会话 | 保留，不拦截气泡查看、播放和长按选字 |

当前没有在输入栏发现引用回复栏或持久化草稿接口，本次不把这些列为已有功能。这里的「保留编辑内容」指会话页存活期间的文本、选区和 @ 状态，不等于新增跨重启草稿功能。

现状问题：

- 实心横条、矩形输入区与多个强调色图标较重；＋在输入文字后被发送按钮替换。
- 多数入口点击区域为 32pt；应扩大至至少 44×44pt。
- 列表底边约束到 inputBar.top，玻璃下没有消息内容，单换 blur 效果有限。
- 键盘高度直接用屏幕通知坐标计算，尚未统一键盘与自定义面板的切换时序。
- 语音提示写着「上滑取消」，但 touchUpOutside 仍走发送；权限异步返回也缺少按压会话校验。

## 3. 布局与视觉规格

### 3.1 默认布局

```text
消息列表（可从输入栏后方滚过）

  ( ＋ )   ╭───────────────────────────╮
           │ 发消息…          ☺    波形 │
           ╰───────────────────────────╯
                    Home indicator
```

输入文字后：

```text
  ( ＋ )   ╭───────────────────────────╮
           │ 明天下午见       ☺    ↑   │
           ╰───────────────────────────╯
```

波形表示「切换语音输入」，不是点击后立即录音，也不是语音转文字。↑ 表示「发送」，有文本才出现。表情图标始终保留；表情面板开启时变成键盘图标。左侧＋展开更多时变为×，无文字或有文字都能点击。

### 3.2 尺寸（初始设计值，单位 pt）

| 项目 | 标准值 | 自适应规则 |
|---|---|---|
| 两侧留白 | 12 | 横屏遵守安全区域；窄屏可降至 8 |
| ＋外圆 | 48×48 | 命中范围至少 44×44，不与输入区重叠 |
| ＋与胶囊间距 | 8 | 不靠放大按钮命中区侵占间距 |
| 输入胶囊 | 最小高 52，圆角 26 | 多行时圆角保持约 26，不能一直取高度一半 |
| 输入正文 | 17，系统字体 | UIFontMetrics / Dynamic Type；实际行高决定高度 |
| 输入左右内边距 | 左 14，右侧控件独立槽位 | UITextView 不延伸到按钮下方 |
| 表情/尾部操作槽 | 各 44 | 图标约 20–22；发送彩色圆直径 32–36 |
| 输入区最大高度 | 常规字号约 5 行、上限约 120 | 无障碍字号重新计算，短屏优先保留编辑与收起能力 |
| 与底部安全区域距离 | 8 | 键盘打开后与键盘顶部保留 6–8 |
| 自定义面板 | 常规初始 260 | 参考最近停靠键盘高度，限制在可用高度内；横屏和大字号可滚动 |

以 375pt 屏宽计算，左右留白 24 + ＋48 + 间距8，胶囊可用宽度 295；扣除左右控件后仍保留主要文本区域。320pt 小屏必须实测，不以缩小点击范围解决拥挤。

多行时＋、表情和发送保持靠底部行对齐，文本向上增长。保持同一个 UITextView 实例，不在有文字/无文字时重建视图。

### 3.3 材质层级

1. **悬浮操作层**：＋圆和输入胶囊使用同一套中性玻璃材质，文字与图标清晰实色。普通图标用 Theme.textPrimary/Secondary，发送用 Theme.accent 与 Theme.textOnAccent。
2. **正文编辑层**：以可读性为先；玻璃内部必要时加低强度语义色承托，不再套第二块模糊玻璃或实心矩形。
3. **功能面板层**：表情和更多属于密集内容区，采用 Theme 的稳定实体/高不透明度背景。只对顶部轮廓、收起控件做轻量材质，不让每个表情和功能格都成为玻璃球。
4. **底部保护层**：透明到语义背景的短渐变覆盖 Home indicator 附近；避开大面积白蒙层，不影响消息上方区域。装饰层不接收触摸。

明亮模式保留薄白高光和柔和阴影；暗色模式降低白边强度，避免灰白发光边。现有 Theme 白天蓝、夜间绿的强调色保持一致，不固定成 Apple 信息的绿色。

截图中能辨认出下方文字重影；本方案只让背景轮廓与色彩透出，不把可清晰阅读的消息字形叠在输入文字下面。优先用 regular 类材质，不能为了透明度牺牲编辑可读性。

## 4. 输入与面板交互

### 4.1 文本与发送

- 点击胶囊进入系统键盘；Return 保持换行，发送通过↑完成。
- 有非空白正文才允许发送；中文 markedTextRange 非空时不发送未确认的组合文本。
- 切换表情、更多、语音均保存正文、selectedRange、@元数据和滚动位置。
- 发送继续调用 onSendText，不改协议或引入新的发送队列；保持当前交给 ViewModel 后清空编辑区的时机。网络失败展示与重试复用现有逻辑。
- 发送后键盘/表情维持当前状态，方便连续输入；↑变回语音图标，＋不位移。
- 从相册、文件、位置选择器取消返回时，不自动打开键盘；保留进入前编辑内容，恢复进入前的自定义面板。通话开始则收起输入面板。

### 4.2 表情

- 点☺：键盘切换到表情面板；再次点键盘图标：回到系统键盘。
- 沿用现有表情库和退格能力，横向分页。实际落地需核验 UICollectionViewFlowLayout 的分页排列；如不符合每页7×3的视觉顺序，改用按页分组布局。
- Emoji 插入到当前选区，不追加到末尾；删除遵守组合 emoji 字符簇和 @ 整块删除规则。
- 常规字号保持7列×3行；超大字号或低高度适当减列/滚动，不能裁切控件。

### 4.3 更多功能

沿用底部面板而非全屏模态菜单，减少偏离现有操作习惯；＋常驻解决「打好文字后还想发附件」的问题。

```text
  相册       拍摄       文件       位置
  语音通话   视频通话                  （仅单聊）
```

- 图标承托约56–60，圆角16，标题完整显示，整个图标和文字区域可点。
- 单聊两行；群聊隐藏通话并回收无意义空白，面板采用对应可用高度。
- 展开更多不清空文字，尾部仍可发送正文；面板中只显示项目真实已有能力，不放红包、付款、位置共享等占位按钮。

### 4.4 语音

点击波形后进入显式语音模式：

```text
  ( ＋ )   ╭───────────────────────────╮
           │ ⌨      按住说话       ☺  │
           ╰───────────────────────────╯
```

- ⌨切回文字并恢复原文。点表情明确切回文本模式并展开表情，避免「语音模式下往不可见输入框插字」。
- 按住中央按钮才开始录音；录音中展示时长、可选音量反馈和明确的取消区域。
- 采用一套追踪按下/移动/松开的录音事件，不把普通 long press 与 UIButton touchDown 同时绑定。
- 上移约64pt进入待取消，回落到约44pt内恢复发送意图，提供滞回避免边缘抖动。阈值是设计初值，真机调整。
- 松手时仅在 recording 状态且意图为发送时发送；cancelArmed、系统取消、退后台、退出页面、音频中断均取消并清理临时文件。
- 沿用≥1秒条件，过短给出「说话时间太短」。权限未获批时只说明用途/引导设置，不显示已经录音；第一次授权结束后要求重新按住，不自动开始旧的录音请求。
- 每次按压分配 sessionID，异步权限返回、转换回调必须匹配有效会话，避免松手后突然录音或重复发送。
- 正文非空时尾部为发送，避免发送与录音共用同一个手势入口；如需在保留文字时发语音，在更多面板加入「语音消息」快捷入口，明确区别于「语音通话」。
- 不新增语音转文字输入或锁定录音等能力；无障碍用户可使用明确的开始/停止/取消辅助操作，复用同一录音结果链路。

## 5. 状态模型与键盘布局

### 5.1 单一可渲染状态

替代当前 panelState + isVoiceMode 的自由组合：

```text
mode: text | voice
surface: collapsed | keyboard | emoji | more
recording: idle | requestingPermission | recording | cancelArmed | converting
editor: text + selectedRange + mentionTokens
```

合法性约束：keyboard/emoji 必须为 text；voice 仅允许 collapsed/more；recording/cancelArmed 时 surface=collapsed，禁用会打断录音的＋与模式切换入口；converting 可以恢复编辑，但禁止重复消费同一录音结果。权限请求结束回到 idle 等待重新按压。

主要转移：

| 当前状态 | 操作 | 结果 |
|---|---|---|
| 收起 / 键盘 | 点表情 | text + emoji |
| emoji | 点键盘图标 | text + keyboard |
| 任意非录音状态 | 点＋ | 当前mode + more；再次点则收起 |
| voice | 点表情 | text + emoji，保留原文 |
| text空正文 | 点波形 | voice + collapsed |
| voice | 点⌨ | text + keyboard |
| keyboard/emoji/more | 点消息区域 | collapsed，保存编辑内容 |
| more | 选择媒体 | 记录恢复状态，收起后呈现选择器 |

### 5.2 列表与遮挡计算

- 列表视图延伸到会话内容底部；composer 作为同级覆盖层，消息滚动时能从悬浮玻璃后方经过。
- 通过唯一的底部布局协调器计算遮挡，不同时叠加旧键盘通知偏移、keyboardLayoutGuide 和额外 safe area。
- 系统键盘以 iOS15+ keyboardLayoutGuide 为首选；自定义面板占用同一底部区域，dock 位于其上方。外接键盘、浮动键盘不套用全宽软键盘高度。
- 计算底部 inset 时先确定 composer 的视觉顶部相对列表 viewport 的遮挡高度 O。目标总底部 inset 为 O + 8；写入 contentInset.bottom 时扣除系统已计入的 adjustedContentInset 差值，避免双算安全区。滚动指示器同源更新。
- 面板关闭时仍留足 dock 高度的滚动余量，列表滚到底后最后一条完整处于 dock 上方；滚动中的历史内容可以经过玻璃下方。
- 面板切换前记录「是否接近底部」和可见行 anchor。接近底部则维持底部；正在看历史则按稳定行ID+屏幕偏移还原，不能因展开面板强制跳最新。
- 当前新消息/AI流式内容的自动滚动逻辑另有实现，本次不顺带改变其产品策略；必须验证它与新 inset 协调不冲突。
- 键盘↔面板切换由一个 transition token 管理；过渡期保留原占位高度，等待目标几何信息后统一提交，忽略旧转移的迟到回调。系统键盘动画使用通知提供的时长与曲线，不能固定0.25秒造成两段动画。
- 透明空隙放行给消息列表，只有实际控件和展开面板接收触摸；保护渐变不参与 hitTest，避免整条底部透明区域成为隐形遮挡。

## 6. 技术适配与组件边界

### 6.1 两级材质实现

| 环境 | 实现 | 说明 |
|---|---|---|
| 当前 Xcode15.2 / iOS15+ | UIVisualEffectView + UIBlurEffect(.systemMaterial 或 .systemThinMaterial)，少量动态承托色、细高光、阴影 | 玻璃风格回退，可立即在当前工程实施；不具备系统原生折射/融合 |
| 支持 iOS26 SDK 的工具链 + iOS26+ | UIGlassEffect，必要时使用 UIGlassContainerEffect 协调相邻材质 | 原生 Liquid Glass；具体使用 regular 类效果，清晰度由系统材质优先负责 |
| 减少透明度 | 语义实体背景 | 按钮轮廓、布局与功能保持一致 |

仅添加 `if #available(iOS 26, *)` 不能让 Xcode15.2 认识新 API。近期采用纯旧SDK实现；原生实现随工具链升级再加入，并以编译期 SDK/编译器条件与运行时 availability 双重隔离。不使用 NSClassFromString/KVC/私有 API 绕过 SDK 限制。

复用 GlassTabBar 的视觉方向，提取合适的材质封装；不直接复用其 CADisplayLink、横滑选中手势和选中块。原生实现采用系统效果，关闭回退层重复的边框/模糊，避免叠加出双层玻璃。

### 6.2 文件职责（建议）

| 文件 | 责任 |
|---|---|
| MessageInputBar.swift | 兼容现有对外回调，组合输入、按钮和面板，统一状态渲染 |
| ComposerState.swift（新增） | 模式、面板与录音状态、合法转移，尽可能不依赖UIKit |
| ComposerGlassBackgroundView.swift（新增） | 阴影/裁剪/材质层分离，主题与无障碍降级 |
| ComposerLayoutCoordinator.swift（新增） | 键盘/面板几何、inset、列表anchor与转移动画 |
| VoiceRecordingController.swift（新增） | 权限、session、录音意图、音频会话与临时文件生命周期 |
| EmojiPanelView.swift / ExtPanelView.swift | 保留数据与回调，调整布局与无障碍 |
| ConversationViewController.swift | 保留业务绑定、选择器和上传；接入底部布局协调器 |
| Theme.swift | 新增 composer 专用语义色，避免散落硬编码 |

所有视图和状态入口在主队列调用；编码转换继续后台执行。AppEnvironment 的依赖方式不变，不新增全局单例。本次不需要改 protobuf、服务端、数据库或最低 iOS15部署目标。新增 App 文件通过已有 project.yml sources 目录规则接入；需要生成工程时走脚本。

## 7. 动效、无障碍与性能

- 胶囊高度变化约180–220ms；＋↔×与波形↔发送用淡入淡出/轻缩放，布局槽位不变。键盘动作遵循系统时序。
- 减少动态效果开启时禁用弹簧、形变与装饰波动，保留简单淡入淡出和必要布局变化。
- 不对每个按键叠模糊、不截图每帧重建背景、不常驻 CADisplayLink；录音音量刷新仅在录音期间运行，退后台停止。
- VoiceOver 标签明确区分「语音输入」「发送」「语音消息」「语音通话」；更多开合、录音开始/取消给予合适播报，焦点不落到隐藏控件。
- 正文与背景对比目标至少4.5:1，大字/图标分别按适用标准验收；浅深主题、增加对比度、减少透明度都要测。
- 动态字体扩大后允许栏高和面板布局变化；屏幕空间不足时面板滚动，不能缩小按钮到44pt以下。
- 性能目标以60Hz设备稳定帧预算为基线，支持高刷的设备另测；在真机测量后记录结果，不预先声称达到某帧率。

## 8. 分阶段实施与验收

### 阶段一：状态与功能等价

整理现有回调与录音生命周期，建立状态模型；先验证文本/@/表情/媒体/通话完整保留。重点补录音上滑取消与权限迟到回调问题。

### 阶段二：悬浮结构与旧SDK玻璃材质

调整列表覆盖关系、统一 inset 与键盘/面板布局，再落地＋圆、输入胶囊、功能网格和主题。当前工具链可编译、可装机。

### 阶段三：原生材质升级

具备新 SDK 后接原生材质；维持状态机和业务回调，做原生/回退两路回归。工具链升级是独立前置条件，不阻塞前两阶段。

| 验收维度 | 必测条件 |
|---|---|
